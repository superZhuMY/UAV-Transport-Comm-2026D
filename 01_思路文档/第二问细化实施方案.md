# 第二问细化实施方案

本方案面向“异构无人机多点多架次运输调度”，以[第二问详细建模说明](第二问详细建模说明.md)和已核对的坑点为依据。实施目标是产出可运行程序、80 箱交付记录、逐架次安排、8 架无人机与 14 组电池的资源时间线，以及能独立复核结果的检查报告。本文规定开发顺序、数据结构、算法、验收条件和交付物；文中目录、命令和参数均为拟实施设计，尚未创建求解程序或完成数值优化。

推荐技术路线是“物理仿真与校验 → 单点可行基线 → 多点候选架次 → CP-SAT 联合调度 → 扩展候选并改进 → 独立复算与导出”。候选只预先固定一趟任务的机型、货箱和访问顺序，是否采用、开始时刻及设备占用由同一个调度模型决定。

**一、先固定计算口径，写入配置并保存在每次结果中。**

| 对象 | 本版采用的口径 |
| --- | --- |
| 任务编号与交付 | 使用逐箱清单的原编号；80 箱恰好交付一次；同一服务区可跨不同架次分批完成 |
| 硬时限 | 全部医疗箱与首批箱取并集，共 31 箱；同时适用两类时限时取较早者 |
| 交付时刻 | 同架次、同站的货箱均在整站交接结束时完成，不设置箱间提前交付顺序 |
| 架次开始 | 指固定准备开始；装载、起飞、各站交接、返场分别记录 |
| 初始与复用 | 所有实体机在 O01，电池初始满电；同型共享、异型禁用；用过的电池必须充至 100% 再使用 |
| 电池占用起点 | 满电电池从准备开始分配给该趟任务；这是选定的保守假设 |
| 资源释放 | 无人机返场后可准备下一趟；原电池返场即充电，充满后才可分配给下一趟 |
| 额外设施约束 | 不添加未给定的充电桩、准备工位数量，也不套用中继机的周转时间 |
| 节点与地形 | 节点地面海拔取节点表；沿途高程取原始 DEM；服务区作业海拔为节点海拔加 30 m |
| 航段与能耗 | 节点间水平直线；每站交接后重新爬升；按方向与剩余载荷计算；下降不另加能耗 |
| 完工时刻 | 所有选中运输架次中最晚的返场时刻，不包括任务结束后的充电时间 |
| 本问范围 | 不添加通信、中继或第四问分区约束；第一问组批仅作为候选 |

运输能耗沿用已明确声明的假设：水平能耗为可用电量乘以水平距离与载荷等效航程之比；爬升能耗为含电池机体与当前货物的重力势能增量除以效率。固定为

\[
L_g(q)=L_g^0-(L_g^0-L_g^F)(q/Q_g)^{3/2},
\]

\[
E_{gij}(q)=E_g^{\mathrm{use}}d_{ij}/L_g(q)
+(m_g+q)\,9.81\,h_{ij}^{+}/(\eta_g\,3.6\times10^6).
\]

这两项能耗的展开式为补充建模口径，不能写成题面已经逐字给定。默认返航余量为 20%，整趟能耗约束为 \(E_p\le0.8E_g^{\mathrm{use}}\)，原始航程不再折减。准备、装载和运输交接不额外加入附件未提供的悬停功率能耗；这也是该统一能耗模型的适用边界。

当前已检查的 Python 3.12 环境有 NumPy、openpyxl 和 Pillow，缺少 OR-Tools、pyproj、rasterio。正式开发时先在项目内建立隔离环境，配置这些依赖并记录实际版本；不改写已有捆绑运行环境。OR-Tools 用于 CP-SAT 调度，pyproj 与 rasterio 用于统一坐标和读取栅格地理参考。可视化库在进入绘图阶段再配置。

已有[审查复算_Q1.py](审查复算_Q1.py)属于第一问复算参考：其中能耗公式可供核对，但固定 400 点采样的 `segment_profile()` 不直接作为第二问生产计算函数，单点往返函数也不能代替多点逐航段仿真。保留该脚本，另建第二问模块。

建议的目录如下；原始附件始终作为只读输入。

| 数据对象 | 必需字段 |
| --- | --- |
| Node | `node_id, lon, lat, ground_z, work_z, x_m, y_m` |
| Box | `box_id, zone_id, category, mass_kg, volume_m3, first_batch, expected_s, hard_deadline_s, priority` |
| AircraftType | 型号、含电池空载质量、载重/体积上限、各阶段速度、空载/满载航程、可用电量、余量、效率、准备/装载/交接时间、完全充电时间 |
| Aircraft | 附件实体编号、型号、初始位置 |
| Battery | 合成唯一编号、型号、初始 SOC；例如 `BA01..BA06`、`BB01..BB04`、`BC01..BC04`，注明为程序生成的库存编号 |
| Segment | 起终点、水平距离、最高沿线高程、巡航海拔、两端作业海拔、爬升/下降高度、所经像元索引或其可复核记录 |

输入验收应得到：16 个节点、80 个唯一货箱、总质量 758 kg、总体积 2.011 m³、30 个首批箱、31 个硬时限箱。硬截止 3600/7200/10800 s 分别对应 17/7/7 箱。检查 `S001-MED-02` 的硬截止为 3600 s，S012、S014 的首批医疗箱也取 3600 s。汇总需求与逐箱清单逐区逐类型对账，冲突时列出差异并停止，不能静默丢箱或补箱。

内部质量和体积可用整数克、整数立方厘米表示，避免浮点数使 0.067 m³ 等临界装载出现误判；能耗计算再换算回 kg。SOC 内部采用 0～1 比例，所有字段名注明单位，导出时再转成百分数。

**四、建立 240 条有向航段的几何缓存。**

16 个节点共有 240 个非自身有向节点对。水平距离和最高沿线地形可复用 120 个无向节点对结果，但爬升、下降高度和飞行时间必须按方向计算。

采用 WGS 84 / UTM 49N 定义水平米制直线。读取 DEM 自身的地理参考和栅格类型，特别检查像元中心与边界、PixelIsPoint/PixelIsArea 语义，不手写未经验证的半像元偏移。计算线路与原始 DEM 像元的相交集合；跨坐标系时，应处理投影变换后的线或像元边界，避免只转换线段端点后将曲线粗暴当成完全相同的直线。边界附近采用保守穿格，并做细分收敛检查；不通过重采样后的平滑高程替代原始像元最大值。

对每段保存巡航海拔 \(H_{ij}=\max z_{\mathrm{DEM}}+50\)，爬升高度 \(H_{ij}-z_i^{\mathrm{work}}\)，下降高度 \(H_{ij}-z_j^{\mathrm{work}}\)。如果出现负高度，报告节点表与 DEM 口径冲突，不能静默截为 0 继续计算。航段越界或经过 NoData 时同样单独报告，不得把缺失高程当成 0。

几何验收包括：正反向水平距离和最高地形一致、爬升和下降高度互换、所有航段位于有效范围。用人工可计算的小栅格测试穿过角点、沿网格边界和狭窄高峰的情况；抽取实际长航段和高差航段，绘制高程剖面核对巡航净空。

**五、实现并验证单架次仿真器。**

拟定接口：

```python
simulate_route(type_id, ordered_stops, boxes_by_stop, instance, geometry)
# 返回 RouteEvaluation；输入不包括实际开始时刻，全部时间为相对偏移。
```

`ordered_stops` 记录停靠事件，`boxes_by_stop` 指向每次停靠交付的箱号集合。每箱只能出现一次，每个停靠事件必须交付至少一箱。初版候选优先使用不重复服务区的路线，但仿真器应能表达同区不同停靠事件，避免把搜索简化写死成题目规则。

仿真依次执行：

```text
校验货箱、目的地、机型、初始载重与体积
t = 固定准备时间 + 每箱装载时间 × 总箱数
q = 全部货箱质量
从 O01 出发
对每次停靠：
    读取该有向航段几何
    使用当前 q 计算爬升/巡航/下降时间和航段能耗
    t += 航段时间
    记录抵达作业高度时刻
    t += 基础交接时间 + 本站箱数 × 每箱增加交接时间
    本站各箱 delivery_offset = t
    q -= 本站交付质量
从最后停靠点空载返回 O01
汇总 D、E、返航 SOC 和充至 100% 的时间 c
检查能量、剩余载荷为 0、无遗漏交付
```

返回值应包含 `feasible, rejection_reasons, initial_mass, initial_volume, energy_kwh, return_soc, duration_s, recharge_s, box_delivery_offsets, leg_records, stop_records`。几何量与同机型飞行时间可缓存，但航段能耗必须使用当前剩余载荷。所有候选生成与优化改进都通过该接口重新评价。

充电时间按题面分段计算：当返航 SOC 为 \(s<0.9\)，取 \(T_{\mathrm{full}}[0.65(0.9-s)/0.9+0.35]\)；当 \(s\ge0.9\)，取 \(T_{\mathrm{full}}0.35(1-s)/0.1\)。单独验证 \(s=0,0.9,1\) 分别得到 \(T_{\mathrm{full}},0.35T_{\mathrm{full}},0\)，且 0.9 处连续。

**六、构造单点基线并建立候选池。**

先保留每箱分别由各可行机型直送的候选，提供最基本的覆盖保障。首小时涉及 S001、S002、S006、S007、S010、S012、S013、S014：为这 8 个区生成紧急箱组批，S001 为两箱医疗加一箱水，其他七区为一箱医疗加一箱水。对各型分别评价，再尝试将首轮任务与 8 架实体机匹配；对后续 7200、10800 s 硬截止任务也要保留资源，不能只顾第一小时。

对剩余货箱采用最早可行插入：尝试所有可用同型机与电池组合，候选开始时刻不得早于两者可用时间；按增加的延迟、返场时间和能耗比较。插入失败时允许拆批、换机型、回退此前分配，或调用单点候选上的调度模型修复。未找到基线只能说明这一构造失败，不能判定题目无解。完整基线必须通过独立校验，随后保留其所有架次，确保扩展候选池不会丢掉已知可行解。

再扩展两点、三点等多点候选。组合时同时考虑空间邻近、紧迫程度、卸载重量、体积与地形代价；对短路线尝试全部访问排列。最近邻、截止最早、重货先送三类规则分别提供初始顺序，不把其中任何一种固定成约束。相同类别但首批标志、截止时间、优先系数不同的箱子不能随意合并成同一种需求。

候选记录包含：`candidate_id, type_id, ordered_stop_events, box_ids, duration_s, energy_kwh, recharge_s, delivery_offsets, latest_start_s, source`。由型号、停靠顺序和各站箱号生成稳定去重键。最晚开始时刻取该候选所有硬时限箱的 \(d_b^{hard}-\alpha_{pb}\) 最小值；若为负，直接删除。

安全剪枝只作用于可比较对象。例如同机型、同一货箱集合的两个候选，若一个在所有货箱交付偏移、返场时长、电池恢复占用时长和能耗上都不优，才可删去。不同机型会竞争不同库存，不能仅因 B 的单趟性能更好就删除 A 型候选。

初始候选池可先控制在约 3000～10000 条，以实测内存和求解表现调整；必须保留单箱覆盖候选、已知基线和各型多样性。该规模以及初期最多三站都是搜索策略，不是题目约束，也不构成全局最优证明。

**七、建立 CP-SAT 联合调度模型。**

对候选 \(p\) 定义选中变量 \(x_p\)，开始时刻 \(S_p\)，准备至返场的可选区间，以及准备至返场后充满的可选电池区间。每个货箱恰好被一个选中候选覆盖：

\[
\sum_{p:b\in B_p}x_p=1.
\]

选中候选时约束 \(C_b=S_p+\alpha_{pb}\)，硬时限箱满足 \(C_b\le d_b^{hard}\)。每型号使用两条累计约束：

| 机型 | 无人机区间容量 | 电池区间容量 |
| --- | ---: | ---: |
| A | 4 | 6 |
| B | 2 | 4 |
| C | 2 | 4 |

无人机区间为 \([S_p,S_p+D_p)\)，电池区间为 \([S_p,S_p+D_p+c_p)\)。这两类约束在选择路线和排开始时刻时一起生效；不能先选完路线，再发现电池排不出来。区间均为左闭右开，允许上一任务释放时下一任务立即开始准备。

为避免未选中的候选污染完工时间，另设有效返场变量 \(F_p\)：选中时为 \(S_p+D_p\)，未选中时为 0，并令 \(C_{max}=\max_pF_p\)。未选中候选的开始时刻也可固定为 0 减少对称性。80 箱且每个架次至少交付一箱，选中架次数不超过 80。

调度时间域不直接截断在最后一个硬截止 10800 s。当前候选池内可先取 \(H=80\max_p(D_p+c_p)\) 作为宽松的整数化时间域上界：本题没有任务释放时刻，在固定资源先后关系下将任务向前压紧不会恶化交付时限。已有基线的完工时间可作为求解提示；若延迟优先，不能随意把它变成硬上界，因为更低延迟的另一方案可能让最后返场更晚。

首版采用 1 s 起始时刻网格。物理仿真保存双精度真实时长；调度模型对累计交付偏移、总返回时长和充电时间分别向上取整，而不改变实际爬升或巡航速度。调度预留的返场后不足一秒空隙是资源缓冲，不能记成没有能耗的额外空中悬停。硬截止向下映射到网格；若边界可行性受到取整影响，缩小到 0.1 s 或更细网格复核，不放宽硬时限。最终报告明确区分调度保守时刻与物理复算时刻，模板交付时刻来自同一份可追溯的最终时间线。

**八、分阶段优化目标并记录证明范围。**

先只求可行性，再在候选池内按默认次序优化：

1. 最小化 \(J_{late}=\sum_b\omega_b\max(0,C_b-d_b^{exp})\)。医疗和首批约束始终保持为硬约束。
2. 在已确定的延迟水平下最小化最后返场时刻。
3. 在前两项确定的水平下最小化总能耗。
4. 在前三项确定的水平下减少架次数；同时报告加权交付完成时间辅助判断“都按时但谁更早”。

若前阶段达到求解器最优状态，可固定其最优值推进下一阶段；若仅得到可行解，保留已达到的指标上界继续求解，并标明这是基于当前解的后续改进，不能声称严格词典序最优。能耗可按 \(10^{-6}\) kWh 缩放成整数用于目标系数；物理可行性仍按原始能耗检验，最终用未取整值重算指标。

每阶段记录 `status, incumbent, best_bound, gap（有定义时）, elapsed_s`。即使 CP-SAT 返回最优，也仅证明当前候选池、时间网格及所选建模口径下的结论。另做“允许少量完工时间增加以降低能耗”等受控比较，明确放宽多少，不把不同量纲指标直接随意相加。

**九、扩展候选并做有针对性的改进。**

从当前时间线识别三类瓶颈：紧急箱交付余量小、某型号无人机排队、某型号电池尚未充满。对这些任务生成新候选，重新调用联合调度器，而非只改路线表：

| 改进动作 | 需要重新检查的影响 |
| --- | --- |
| 跨架次移箱、换箱 | 目的地区分、硬时限、全部后续航段剩余载荷、装载体积 |
| 合并或拆分架次 | 固定准备和交接开销、更多停靠的重复爬升、设备并行性 |
| 换机型 | 各型号库存、载荷/体积、飞行速度、交接时间、充电时间 |
| 重排停靠次序 | 有向几何代价、逐站交付时刻与非线性能耗 |
| 增加更远节点或更多停靠 | 检查初始近邻和站数限制是否排除了更好的组合 |

首次可采用每轮保留当前解、增加一批候选、给出固定求解时间限制的循环。启发式失效或求解超时要保留最好已验证方案。连续数轮无改进只能作为本轮搜索停止条件，不能作为全局最优证据；配置和日志中记录候选池上限、每轮时间限制与停止原因。若限制过紧导致不可行，按“补覆盖候选 → 扩展机型/组批 → 扩展顺序/站数 → 检查时间网格与资源冲突”的顺序排查，不能删除硬截止条件来获得所谓可行解。

**十、把资源区间落实到具体编号。**

同型无人机初始状态相同，电池均初始满电且可独立充电，因此可在调度后为各型区间分别着色分配编号。按开始时刻排序，用最小堆保存每个资源的下次可用时间；选择满足 `available_time <= start_time` 的资源，更新其释放时刻。

无人机编号使用附件 U01～U08；电池使用库存表中程序生成的 14 个编号。无人机与电池分别分配，不永久绑定，也不允许异型配对。若在规定数量内不能完成编号分配，应判为区间构造或模型结果有误并回查，不能临时多建一架无人机或一组电池。

**十一、用独立校验器决定结果是否可以交付。**

`check_solution()` 读取原始规范化输入和最终的架次、箱号、机型、设备编号、开始时刻，重新计算结果；不直接相信候选缓存中的能耗、结束时刻或优化器汇总值。可以共享经验证的底层物理函数，但应独立重建载荷、事件顺序和资源占用，并用人工可计算的用例防止公共函数错误。

| 校验项 | 应输出的证据或错误 |
| --- | --- |
| 货箱覆盖 | 80 个箱号恰好一次；明确列出重复、遗漏、未知编号和错投服务区 |
| 交付与时限 | 整站交接完成时刻；31 个硬时限箱的剩余时间，最小余量及对应箱号 |
| 载荷与能量 | 每航段剩余质量、各段能耗、全程能耗和返航 SOC；载重/体积余量 |
| 无人机占用 | 同一编号各趟准备开始至返场不重叠，型号与任务一致 |
| 电池占用 | 同型使用；上一趟实际充满不晚于下一趟准备开始；初始满电；数量不超 6/4/4 |
| 时间口径 | 准备与装载不遗漏也不重复；交接后才进入下一段；完工时刻按最晚返场 |
| 指标一致性 | 延迟、完工时刻、总能耗、架次数均从最终明细重算并与报告相符 |

必须覆盖的边界用例包括：`S001-MED-02` 漏设硬时限；抵达早于截止但交接结束超期；多点任务少算一次重新爬升；正反航段高差不同；返程误带原载荷；电池尚余 65% 但未充满就复用；无人机换满电池而旧电池仍在充电；同一时刻释放与重新占用；SOC 恰为 0.9；安全余量被扣两次；原始 DEM 某狭窄高像元被稀疏采样漏掉。给每个故意错误的测试解明确预期错误码，不仅测试“程序能运行”。

第二问不需要为了校验而逐秒遍历整个运行时域：飞行与交接按事件精确递推，资源冲突按区间端点扫描即可。以后第三问增加连续通信检查时，再引入针对轨迹的空间与时间判定。

**十二、输出文件与阶段验收。**

每次运行目录先保留 JSON/CSV 明细和校验报告，通过校验后再按[结果提交模板](结果提交模板.xlsx)导出第二问的两个工作表。模板原文件保留，只写新的结果副本；其他问题的空表不表示其已完成。

| 文件 | 内容 |
| --- | --- |
| `run_manifest.json` | 输入哈希、配置、依赖版本、随机种子、模型假设、求解状态和边界 |
| `solution.json` | 全部选中架次、货箱、停靠事件、实体与电池编号、计划开始时刻 |
| `transport_sorties.csv` | 模板 Q2_运输架次字段，补充起飞、时长、初始载荷、体积和返航 SOC |
| `box_deliveries.csv` | 80 箱交付时刻、硬/软截止、硬时限余量、超期量与优先系数 |
| `flight_legs.csv` | 有向航段、巡航海拔、剩余载荷、时间和能耗分项 |
| `aircraft_timeline.csv` | 准备、飞行、交接、返场及空闲事件 |
| `battery_timeline.csv` | 分配、返场 SOC、充电开始、充满与下一次分配 |
| `validation.json` | 总体是否通过、每项检查结论、所有失败对象与定位信息 |
| `Q2结果.xlsx` | 按模板填写的运输架次与逐箱交付表 |
| `Q2结果说明.md` | 基线与改进方案指标、选择理由、假设、求解证明范围和复现方法 |
| 路线图、无人机/电池甘特图 | 展示访问顺序、任务并行、设备等待与充电等待 |

按以下门槛逐步推进，不以“优化器有输出”代替验收：

| 阶段 | 可验收产物 | 通过后进入 |
| --- | --- | --- |
| P0 数据与口径 | 输入对账、31 箱硬时限名单、配置与假设记录 | 地形计算 |
| P1 几何与物理 | 240 条有向几何、穿格边界用例、单点/多点及充电手算核对 | 基线求解 |
| P2 完整基线 | 80 箱交付、实体与电池编号、全部硬约束通过 | 多点优化 |
| P3 联合优化 | 多点候选与调度结果、求解状态、相对基线的指标变化 | 候选扩展 |
| P4 搜索与比较 | 不同目标取舍方案、改进记录和停止原因 | 最终导出 |
| P5 独立复算 | 零硬约束违规、模板字段齐全、从保存的配置可复现 | 第二问交付 |

拟定的命令接口可为 `main.py prepare`、`main.py baseline`、`main.py solve`、`main.py validate` 和 `main.py export`，分别对应上述阶段。当前最先实施的工作是 P0 与 P1：把输入、时间定义、DEM 穿格和 `simulate_route()` 做准确，再进入组批和调度优化。
