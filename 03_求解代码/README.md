# 求解代码说明

## 目录

| 路径 | 说明 |
| --- | --- |
| `q2/` | 问题二求解主程序。按 P0→P5 分阶段执行：几何缓存 → 实例装载 → 候选架次生成 → CP-SAT 联合调度 → 仿真校验 → 导出与绘图 |
| `审查复算_Q1.py` | 第一问独立复算，核验《第一问详细建模说明》中的试算数字（最大安全载荷、架次下界） |
| `review_q2.py` | 第二问独立审查。不复用 `q2/validator.py` 的通过标志，从保存的路线字符串与逐箱归属重建架次，另行校验时间、载荷、能耗、充电与资源冲突 |
| `数据整理工具/` | 题面与数据的抽取脚本（DOCX/OMML 公式转文本、多源合并） |

## q2 主程序

模块职责：

| 文件 | 职责 |
| --- | --- |
| `geometry.py` | WGS 84 / UTM 49N 投影、DEM 穿格取高、航段地形缓存 |
| `physics.py` | 载荷相关等效航程、水平与爬升能耗、往返最大安全载荷 |
| `data_io.py` | 实例装载、输入哈希、运行目录与缓存目录定位 |
| `candidates.py` | 候选运输架次生成（组批 + 邻近服务区顺序搜索）与支配剪枝 |
| `scheduling.py` | CP-SAT 联合调度：货箱覆盖、访问顺序、机型与实体机指派、电池周转、开始时刻 |
| `simulator.py` | 按解重建时间轴，逐时刻校验资源占用 |
| `validator.py` | 载质量、体积、能量、返航 SOC、硬时限、资源冲突校验 |
| `export.py` | 按结果提交模板导出工作表 |
| `make_report_docx.py` | 生成结果说明 Word 文档 |
| `main.py` | 命令行入口 |

运行：

```bash
# 完整流程（两阶段：P0/P1 几何与实例准备 → P2 起求解导出）
python main.py all <run_id> [energy_first|sorties_first]

# 仅做 P0/P1（生成几何缓存与实例快照）
python main.py prepare
```

- `<run_id>` 会决定 `runs/<run_id>/` 的落盘位置。
- 求解目标按 `config.json` 的 `objective_order` 词典序推进：`weighted_tardiness → makespan → energy → sortie_count`。
- ⚠️ 多阶段词典序求解**每阶段需重建模型**；同一变量重复 `AddHint` 会导致 `MODEL_INVALID`；求解失败后调用 `solver.Value` 可能取到无效值 → **每阶段成功即快照，失败回退**。

## 可复现前提

`data_io.py` 以 `__file__` 相对定位，要求 `q2/` 的上一级目录中存在：

```
<上级目录>/
├── q2/                ← 本目录
├── 数据/              ← 官方基础数据表 + 镇龙乡地理空间数据
└── 结果提交模板.xlsx   ← 官方结果模板
```

官方原始数据不随仓库分发，需自备。`审查复算_Q1.py` 顶部 `BASE` 为写死的绝对路径，跨机器运行前须改指到本地数据目录。

依赖安装见 `q2/requirements.txt`。注意 `ortools` 在部分国内镜像源缺失，需走官方源。

## 结果落盘

单次运行在 `runs/<run_id>/` 下产出：逐箱交付记录、航段明细、无人机与电池时间轴、架次表、方案 JSON、校验报告与三张图（机队甘特图、电池甘特图、路线图），并按模板导出结果工作簿。
